**Read first, in order:** `agent-tasks/phase5/SHARED.md` → `plan.md` §3.1, §6 (P8 row) → this file. Apply with no discussion.

## What
Mine design tokens from reference decks and hand-tune into shippable token sets:
- Run the existing `BrandProfileExtractor` (F9, already merged — find it in `PptxEditor.Core`) on the 4 REF decks: `pres-pro.pptx`, `REMOVED.pptx`, `AetherLink-Glass-Shareholder-Overview.pptx`, `FusionFest-Architecture-Overview.pptx` (all in `examples/REF/PPTX/`).
- Produce 2–3 design-token JSON sets matching plan §3.1 exactly (`palette`, `fonts`, `shape`, `metrics`), seeded by extraction and hand-tuned where extraction is noisy.

## Why
Design tokens are first-class input to the generator; pre-mined, taste-checked sets are what make generated decks beautiful by default.

## Owns (strict — nothing else)
- `PptxEditor.Core/Generation/Design/` — **data files only** (JSON). No engine code.
- A small extraction runner script under `Generation/Design/` is permitted if needed to invoke the extractor; it must not touch engine code.

## Depends on
- F9 (BrandProfileExtractor) — already merged. Nothing else. You are parallel-safe with P1.

## Acceptance
- 2–3 token-set JSON files in `Generation/Design/`, each conforming to §3.1 shape, each traceable to its source deck(s) (note provenance in an adjacent comment/README inside the owned folder).
- Fonts/palette values actually present in the source decks (no invented brand values; hand-tuning is for metrics/radii only — document it).
- JSON is valid and loadable. Report per SHARED.md contract.
