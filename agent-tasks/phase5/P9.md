# P9 — API + MCP Surface (`deck_generate`)

**Read first, in order:** `agent-tasks/phase5/SHARED.md` → `plan.md` §2, §3.4, §6 (P9 row), §7.1 → this file. Apply with no discussion.

## What
Expose generation to consumers:
- MCP: a `deck_generate` tool in `OfficeEditor.Mcp/` — JSON document in → PPTX + per-slide SVG/PNG previews out (via the existing deck-session and render tooling; follow the established tool patterns in that project).
- API: `POST /api/decks/generate` in `OfficeEditor.Api/` with the same payload/response shape.
- SVG live preview path through TypstBridge (primary backend, per AGENTS.typst.md).

## Why
This is the user-facing surface of Phase 5 — the §7.1 deliverable: "JSON in → PPTX + previews out, warm < 500ms/deck for ≤16 slides".

## Owns (strict — nothing else)
- `OfficeEditor.Api/` (generation endpoint + services)
- `OfficeEditor.Mcp/` (`deck_generate` tool)
- `OfficeEditor.Api.Tests/`, `OfficeEditor.Mcp.Tests/` (corresponding tests)

## Depends on
- **P1–P5 merged** (model, layout, both emitters). Do not start before.

## Acceptance
- `deck_generate` + REST endpoint: valid doc per §3.4 → PPTX + per-slide previews; invalid doc → the P1 validator's actionable errors surfaced verbatim (HTTP 400 / MCP error).
- Warm-path timing measured and reported (< 500ms/deck for ≤16 slides target; report actuals).
- Follow existing session/tool patterns; `dotnet test` green incl. API+MCP test projects.
- Report per SHARED.md contract.
